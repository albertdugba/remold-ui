When the page changes, Remold compares what was on screen with what is there now, works out which element became which, and moves each one to its new place with a spring. Sort the list below: the whole list is rendered again, and nothing in it has an animation id.

## Why no ids

Layout animation tools usually pair elements by a name you give them, such as `layoutId` or `view-transition-name`. That works until the markup is rewritten: a server response, a different component rendering the same data, content generated by a model. Remold pairs elements by what they are instead (their text, images, size, position and surroundings), so it also works on markup you don't control.

## Packages

| Package               | What it does                                                                                       |
| --------------------- | -------------------------------------------------------------------------------------------------- |
| `@remold-ui/react`  | Components and hooks for React. Start here if you use React.                                       |
| `@remold-ui/dom`    | Plain JavaScript, with any framework or none: transitions for any element, text morphing and connectors. |
| `@remold-ui/canvas` | Animated scenes and particles drawn on a canvas.                                                   |
| `@remold-ui/core`   | The matching, springs and shape morphing everything else is built on. No DOM, so it runs anywhere. |

## Principles

- **Interruptible.** Change state again mid-animation and everything heads for the new place from where it is, at the speed it was going.
- **Springs, not durations.** Motion is described as `{ duration, bounce }`, the way SwiftUI does it.
- **Reduced motion.** When the system asks for less motion, changes happen at once.
- **Small.** The core has no dependencies, and each package can be used on its own.

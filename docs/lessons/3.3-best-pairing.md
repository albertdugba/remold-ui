# Lesson 3.3 · Best pairing (script for Claude)

**Files:** `packages/core/src/match/hungarian.ts` (`hungarian`, `assign`), also used by `morph/match.ts` for shapes now.
**Goal:** Albert can show by hand why greedy pairing fails, and explain what the threshold is for.
**Mode:** fast, as in 3.1.

## A · Story
Two kids, two toys. Kid A likes toy 1 a lot (cost 1) and toy 2 nearly as much (2). Kid B likes toy 1 (2) but hates toy 2 (10). Greedy gives A toy 1 first, so B is stuck with toy 2: total 11. Swapping gives 2 + 2 = 4. The test "finds the cheapest total" is exactly this.

## B · Read
- Don't derive the potentials (`u`, `v`). Explain: the algorithm keeps "prices" on rows and columns so it can tell when swapping partners lowers the total. The comments name the method (Jonker–Volgenant style).
- More rows than columns: solve the transpose.
- `assign`: similarity → cost, and **the threshold**. Ask: why is "unmatched" better than a weak match? *(A wrong match animates a button into a photo, which looks broken. An unmatched element just fades.)*

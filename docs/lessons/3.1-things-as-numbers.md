# Lesson 3.1 · Things as numbers (script for Claude)

**Files:** `packages/core/src/match/nodes.ts` (`MatchNode`, `prepare`, `ancestors`, `descendants`).
**Goal:** Albert can explain every field of the feature sheet, and why the matcher never sees ids, classes or tags.
**Mode:** fast. The code is written and passing, so teach by story → predict → read → break it → run. One step per message, then wait.
**Code standard:** production open source. No lesson references in `packages/`.

## A · Story
You get two photos of a room, before and after someone tidied it. You can't read labels on anything, but you can still say "that lamp is that lamp": same shape, similar place, same colour. The matcher describes each element the way you'd describe the lamp.

## B · Read `MatchNode`
- `kind`: heading, text, control, media or box, as a person would see it, not the HTML tag.
- `text`, `media` (an identity for images), the box in **root widths**, `parent`, and paint.
- Ask: why divide positions by the root's width? *(So a 1000 px desktop page and a 400 px mobile page are comparable. See the Settings scenario.)*
- Ask: why no `id` or `className`? *(Those are exactly what AI rewrites and server swaps change. That's the whole point of Remold.)*

## C · `prepare`
- `subtree`: a container is described by what's inside it. Ask why that's built **backwards** through the list. *(Children come after parents, so walking backwards sees every child first.)*
- `hasContent`: only things with text or media get to vote later (3.4).
- **Break it:** allow `parent >= index`. Which test fails, and what could go wrong? *(A cycle, which would loop forever in `ancestors`.)*

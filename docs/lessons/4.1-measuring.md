# Lesson 4.1 · Measuring (script for Claude)

**Files:** `packages/dom/src/extract.ts` (`readNodes`, `parseColor`, `fingerprint`), `extract.test.ts`, and `test-utils.ts` (fake layout for happy-dom).
**Goal:** Albert can explain which elements are kept, how the page becomes `MatchNode`s, and how to test DOM code without a browser.
**Mode:** fast. The code is written and passing, so teach by story → predict → read → break it → run. One step per message, then wait.
**Code standard:** production open source. No lesson references in `packages/`.

## A · Story
A person looking at a page doesn't see `<div class="wrapper">`. They see a card, a title, a button, a photo. `readNodes` writes down only what a person would notice, and skips invisible wrappers.

## B · Read
- Kept: own text, media, controls, painted boxes. Ask: why skip unpainted wrappers? *(They change every time markup is rebuilt, but nobody can see them.)*
- Inline formatting folds: `Total: <b>€154</b>` is one text.
- `data-rm-ignore` skips a subtree (Remold's own exit layer uses it).
- 🐛 A real bug found during the build: `Number("")` is 0, so an empty computed opacity counted as invisible and **nothing** was read. Show him the fix (`parseFloat`) and ask why `Number` and `parseFloat` differ on `""`.

## C · Testing without a browser
happy-dom has no layout, so `useFakeLayout()` makes `getBoundingClientRect` read a `data-box` attribute. Ask: what can't these tests prove? *(That real CSS lays things out where we think. That's why 4.2 checks in real Chrome.)*

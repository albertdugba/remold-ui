# Lesson 2.1 · Time (script for Claude)

**Files:** `packages/dom/src/frames.ts` (`frames`, `createFrameLoop`, `prefersReducedMotion`) and `frames.test.ts`.
**Goal:** Albert can explain why animation uses real elapsed time, why there's one shared loop, and how the fake scheduler makes it testable.
**Mode:** fast. The code is written and passing, so teach by story → predict → read → break it → run. One step per message, then wait.
**Code standard:** production open source. No lesson references in `packages/`.

## A · Story
A flip-book: the screen shows a new page about 60 times a second (120 on newer phones). If each page moved the ball 1 px, it would go twice as fast on a 120 Hz phone. So each page asks "how much **time** passed?" and moves by speed × time.

## B · Predict
- Frames arrive 16 ms, 8 ms, then 25 ms apart. What `dt` values do callbacks see? *(0.016, 0.008, 0.025 s. That's the first test.)*
- The tab was hidden for 5 seconds. What should `dt` be? *(Capped at `maxDelta`, so things carry on instead of teleporting.)*

## C · Read
- One `Set` of callbacks and one `requestAnimationFrame` for all of them, which sleeps when the set is empty. Ask: why not one rAF per animation? *(Many rAF callbacks per frame cost more, and they'd see slightly different times.)*
- `platform ??= browserScheduler()` on first use. Ask: what breaks in Next.js if we touched `requestAnimationFrame` at import time? *(Server rendering crashes, because there's no `window` there.)*
- An error in one callback is reported with `queueMicrotask` and doesn't stop the others.

## D · Break it
Remove `Math.min(maxDelta, …)`. Which test fails? *("caps long stalls")*

**Goal:** Albert can explain how a hooks-only component snapshots the page before React commits, and the Base UI contract every part follows.
**Mode:** fast. The code is written and passing, so teach by story → predict → read → break it → run. One step per message, then wait.
**Code standard:** production open source, hooks only, Base UI-style API.

## A · The timing problem
Remold must read the page *before* the DOM changes; effects run *after*. No hook runs in between.
- The answer is React's documented pattern for adjusting state when a prop changes: during the render where `trigger` changes, call `setPending(prepareTransition(element))`. Preparing **only reads** the page (dom's `prepareTransition` doesn't stop anything until `play()`), so if React throws that render away, nothing has happened.
- A layout effect then calls `pending.play()` after commit, before paint.
- Ask: why keep the element in state (`ref={setElement}`) rather than a ref? *(Reading `ref.current` during render is off-limits; state isn't.)*
- Verified in Chrome (development build, no warnings): no jump, momentum kept when interrupted.

## B · The Base UI contract (every part)
- Parts on a namespace: `Remold.Root`, `.Text`, `.Scene`, `.Ignore` (`export * as Remold`). Types live on the part: `Remold.Root.Props`, `Remold.Root.State`.
- `render`: an element (props and refs merged, class names joined) or `(props, state) => element`. `className`: a string or `(state) => string`.
- State as `data-rm-*` attributes: `data-rm-animating`, `data-rm-layout`, `data-rm-focused`.
- Controlled or uncontrolled: `focused` / `defaultFocused` / `onFocusedChange`, and `layout` / `defaultLayout`.
- `ref` is always the DOM element; extra controls go through `actionsRef` (`Scene.Actions`: `points`, `pick`, `anchor`, `box`, `redraw`).
- `onX` callbacks fire for **user** actions only, never for programmatic changes.
- 🐛 Real bug found while testing: a refused controlled focus left the canvas showing the refused object. Two fixes: the scene's `focus()` no longer fires `onFocusChange`, and the React part puts the controlled value back.

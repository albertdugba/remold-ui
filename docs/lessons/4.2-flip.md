# Lesson 4.2 · FLIP with springs (script for Claude)

**Files:** `packages/dom/src/transition.ts` (`transition`), `transition.test.ts`, and the playground's "Markup rewritten from scratch".
**Goal:** Albert can explain First, Last, Invert, Play, and what Remold adds: matching, springs and interruption.
**Mode:** fast, as in 4.1.

## A · Story
FLIP: remember where it was (**First**), let it jump to its new place (**Last**), pretend it didn't by pushing it back with a transform (**Invert**), then let the transform go to zero (**Play**). Remold adds the hard part: knowing which new element *was* which old one, with no keys.

## B · Read the steps in `transition()`
1. Freeze any running transition. 2. `readNodes` + clone the page. 3. Run `update`. 4. Read again, `matchNodes`. 5. Records: pairs spring their box, arrivals fade in, departures fade out as clones taken **before** the update. Ask why before. *(Frameworks often reuse an element and change its text, so a clone taken after would show the new text fading out.)*
- `translate` and `scale` properties, not `transform`, so a stylesheet's own `transform: rotate()` survives. Ask what `applyRecord` does when the transform is the identity, and why. *(It writes nothing: even `scale: 1` makes a containing block for `position: fixed` children.)*

## C · Interruptible (the core rule)
Verified in real Chrome: interrupting Board → List at 150 ms, the title read (433.4, 382.6) before and after the click (no jump), then kept moving right to 442.6 before turning round (momentum). Ask him which lines carry the velocity. *(`carried?.channels…velocity`.)*

## D · Break it
Remove the `velocity` argument in `boxChannels`. Rebuild the playground, click two views quickly, and feel the jerk.

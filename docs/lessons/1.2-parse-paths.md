## Part A · `tokenize`: chopping text into pieces

### A1 · Story
An SVG path is a note to someone holding a pen: "move here, draw a line there". The note is one long string like `"M10 20 L30,40"`. Before we can follow it, we chop it into pieces, the way you'd split a sentence into words. Those pieces are **tokens**.

### A2 · Predict (ask, wait)
- What should `tokenize("M10 20 L30,40")` give back?
- Trickier: `"M10-5"` has no space. Is that one number or two?

*(Answers: `["M", 10, 20, "L", 30, 40]`. Two numbers: a minus sign starts a new number, so it's `["M", 10, -5]`.)*

### A3 · Type-along: the skeleton
Ask Albert to type this into `tokenize`, replacing the `throw`. Rename `_d` to `d`.

```ts
const tokens: Token[] = [];
let i = 0;
while (i < d.length) {
  const ch = d[i]!;
  // we'll fill this in, one kind of character at a time
}
return tokens;
```

Explain:
- `i` is our finger, pointing at one character at a time.
- `!` tells TypeScript "I promise this exists", because `noUncheckedIndexedAccess` is on.

Ask him: *what's wrong with this loop if we run it right now?* (Answer: `i` never moves, so it loops forever. A good reason not to run it yet.)

### A4 · Your turn: skip the gaps
He writes: if `ch` is a space, comma, tab or newline, move `i` forward by one and `continue`.
- **Hint 1:** a regex like `/[\s,]/` can test a single character.
- **Hint 2:** `if (/[\s,]/.test(ch)) { i++; continue; }`. Only give this if he's stuck.

### A5 · Type-along: letters

```ts
if (/[MmLlHhVvZzCcSsQqTtAa]/.test(ch)) {
  tokens.push(ch);
  i++;
  continue;
}
```

Ask why we list *all* the letters, including curves we don't handle yet. (Answer: the tokenizer's job is just to chop. Deciding what's supported is the parser's job. Each part has one job.)

### A6 · Tiny experiment: sticky regex
Have him open `node` in the terminal and type:

```js
const r = /\d+/y;
r.lastIndex = 2;
r.exec("ab123cd");      // what does this print?
r.lastIndex;            // and this?
```

Explain:
- `y` means **sticky**: the regex only matches exactly where `lastIndex` points, never further along.
- After a match, `lastIndex` jumps to just after it. That's exactly "read a number starting at my finger".

Ask: what happens with `r.lastIndex = 0` on the same string? (No match, because sticky doesn't search ahead.)

### A7 · Your turn: numbers
He writes the number branch with a sticky regex that matches:
- an optional sign;
- digits with an optional dot, *or* a dot followed by digits;
- an optional exponent.

Then he pushes `Number(match)` and moves `i` to `lastIndex`.

He should make these tests pass: "splits letters and numbers", "handles squashed numbers", "reads exponents".
- **Hint 1:** test it on `"10"`, `"-5"`, `".5"`, `"1e2"` in the node REPL first.
- **Hint 2:** the pieces are `[-+]?`, then `(?:\d+\.?\d*|\.\d+)`, then `(?:[eE][-+]?\d+)?`.
- **Hint 3:** walk through why `".5.5"` becomes two numbers. The second dot can't be part of the first number, so the first match stops there.

### A8 · Your turn: anything else is a mistake
If nothing matched, `throw` an error that says which character and where. Then the "rejects characters" test goes green.

### A9 · Explain it back and break it
- Ask: why must `i` move forward in *every* branch?
- Break it: remove `[-+]?` from the number regex. Predict which test fails, then run it.

## Part B · `parsePath`: following the pen

### B1 · Story
Now imagine actually holding the pen:
- You always know **where the pen is** (`x`, `y`).
- You remember **where this shape started** (`startX`, `startY`), so "close it" (`Z`) knows where to go back to.
- You remember **the last instruction** (`cmd`), because SVG lets people be lazy: `M0 0 10 0 10 10` means "move, then line, then line".

### B2 · Predict (ask, wait)
- `parsePath("m10 20 l5 5")`: where does the second point end up? *(15, 25. Lowercase means "relative to the pen".)*
- `"M1 1 L5 1 Z l2 0"`: where is the pen after `Z`, and so where does `l2 0` go? *(Back at (1, 1), so (3, 1).)*

### B3 · Type-along: the setup

```ts
const tokens = tokenize(d);
const out: PathCommand[] = [];
let x = 0, y = 0, startX = 0, startY = 0;
let cmd: string | null = null;
let i = 0;
const num = (): number => {
  const t = tokens[i++];
  if (typeof t !== "number") throw new Error(`Expected a number at token ${i - 1}`);
  return t;
};
```

Explain that `num()` is a helper that "takes the next number off the pile, or complains". Point out that the "explains mistakes" test expects `/number/` in that message.

### B4 · Your turn: the main loop, `M` and `L` only (absolute)
Loop while `i < tokens.length`:
- If the next token is a string, it's a new command: store it in `cmd` and advance.
- Otherwise reuse the last `cmd`.
- If there's no `cmd` yet, or the first command isn't `M`/`m`, throw an error containing "start with M".

For `M`: read two numbers, set `x` and `y`, set the start, push the command, then **switch `cmd` to `L`** (that's the lazy-repeat rule). For `L`: read two numbers and push.

Target tests: "reads absolute moves and lines", "treats extra pairs after M as lines".
- **Hint 1:** `const letter: string = cmd.toUpperCase()` lets one branch handle both cases.
- **Hint 2:** after `M`, set `cmd = rel ? "l" : "L"`.

### B5 · Your turn: lowercase means relative
Add `const rel: boolean = cmd === cmd.toLowerCase()`. When `rel` is true, add the pen's position to the numbers you read. Target test: "turns relative commands into absolute positions".

### B6 · Your turn: `H` and `V`
These only change one coordinate, but they still output an ordinary `L` with both `x` and `y`. Target test: "turns H and V into ordinary lines".

### B7 · Your turn: `Z`
Push `{ type: "Z" }`, put the pen back at `startX`/`startY`, and set `cmd = null`, because `Z` takes no numbers. Target test: "Z closes the shape".

### B8 · Anything else
Any other letter (curves) throws "comes in lesson 1, part 2". Then all 10 tests are green. 🎉

### B9 · Explain it back and break it
- Ask: why does `M` switch `cmd` to `L`? What would `M0 0 10 0` produce without that line?
- Break it: forget to reset the pen on `Z`. Which test fails, and what wrong number does it show?

# Lesson 1.6 · Fast in-betweens (script for Claude)

**Files:** `packages/core/src/morph/morph.ts` (`createMorph`, `lerpBuffers`, `SubpathLayout`) and `morph.test.ts`.
**Goal:** Albert can explain the packed layout, why `Float32Array`, and why `t` is allowed outside 0–1.
**Mode:** fast, as in 1.5.

---

## A · Story
Instead of a box of loose toys (objects with `x`/`y`), we put every number in one long egg carton, always in the same order. Shape A has a carton and shape B has an identically laid-out carton. A frame is: for each slot, `lerp(a, b, t)`. That's it.

## B · The layout
- Per subpath: 2 numbers for the start point, then 6 per segment (handle 1, handle 2, end). The next segment starts where this one ended, so start points aren't repeated.
- Predict: how many numbers for a closed square? *(2 + 4 × 6 = 26. The test checks this.)*
- `SubpathLayout` says where each subpath starts in the carton.

## C · Why `Float32Array`?
- Ask him first. *(Flat, fixed-size memory: no objects for the garbage collector to chase, and engines run the loop at near-native speed. Half the memory of normal numbers, and screen pixels don't need more precision.)*
- Note `at()` reuses one scratch buffer unless you pass `out`, so there are no allocations per frame. Ask: what bug does that cause if someone keeps the returned array from frame 1? *(It changes under them on frame 2. That's why the docs say to copy it.)*

## D · t outside 0–1
- Springs (Part 2) overshoot: a bouncy spring goes to 1.08, then back. Clamping would flatten the bounce. Test: "goes past B when t > 1".

## E · Break it
- Make `lerpBuffers` clamp `t` to [0, 1]. Which test fails? *(The overshoot test.)*

# Lesson 4.3 · Boxes inside boxes (script for Claude)

**Files:** `packages/dom/src/transition.ts` (`computeVisual`, `applyRecord`, anchors).
**Goal:** Albert can derive the counter-transform on paper.
**Mode:** fast, as in 4.1.

## A · Story
Stretch a photo of a card to twice its width and the text on it stretches too. To keep the text normal, the text must squeeze itself by the same amount the card stretched.

## B · The maths (do it on paper together)
The anchor (nearest animated ancestor) maps its layout box L_A onto its visual box V_A. Any point inside it is mapped the same way. To put a child at visual box V, find W (its box *before* the anchor's transform): `W.x = L_A.x + (V.x − V_A.x) · L_A.w / V_A.w`, and the same for y and the sizes. Then the child's own scale is `W.w / L.w`.
- Why only the *nearest* animated ancestor? *(Everything above it is already folded into how the anchor maps its box.)*
- Test: "corrects children so a growing card doesn't stretch them": card scale 0.5, title scale 2.
- Real Chrome: the card went 3.35 × 0.86 while the title stayed 114 px wide every frame.

## C · Text scales uniformly
Text and labelled controls use one scale (from the font-size change), so glyphs never squash.

# Lesson 4.4 · View transitions (script for Claude)

**Files:** `packages/dom/src/view-transition.ts` (`viewTransition`), `packages/core/src/motion/css.ts` (`springToCss`).
**Goal:** Albert can explain the naming trick, and when to choose `viewTransition` over `transition`.
**Mode:** fast, as in 4.1.

## A · The trick
The browser needs matching `view-transition-name`s on old and new elements, but we only know the matches *after* the update. So: name every old element uniquely before the snapshot, then once `update` has run, give each new element its old partner's name.

## B · Springs in CSS
`springToCss` samples the spring into `linear(…)`. Verified in Chrome: Remold's groups ran 771 ms with the spring curve; only the browser's `root` group kept its 250 ms default.

## C · The trade-off (important)
Browser-run animations can't be redirected mid-flight with momentum: a new call skips to the end. That breaks the "always interruptible" rule, so `transition()` is the default, and `viewTransition` is for big changes where compositor performance matters. It falls back to `transition()` without the API, with reduced motion, or with over 400 elements.

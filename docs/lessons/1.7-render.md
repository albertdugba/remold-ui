**Files:** `packages/core/src/render/svg.ts` (`toPathData`), `render/canvas.ts` (`drawPath`, `PathSink`), `render/render.test.ts`, and `apps/playground` (the "Shape morph" section).

**Mode:** fast, as in 1.5.

## A · Story
The egg carton of numbers is useless until someone reads it out loud as drawing instructions. There are two readers: one writes an SVG `d` string, and the other calls canvas pen methods directly.

## B · `toPathData`
- Always `M`, then `C` × segments, then `Z`, even for straight lines. Ask why we don't shorten straight bits to `L`. *(Every frame must have the same commands, or CSS `d: path()` transitions, SMIL and Lottie can't interpolate them.)*
- Precision: two decimals is plenty for screens and keeps strings short. `-0` never appears, because `String(-0)` is `"0"`.

## C · `drawPath` and `PathSink`
- `PathSink` is a tiny interface (`moveTo`, `bezierCurveTo`, `closePath`) that `Path2D` and canvas contexts already satisfy. Ask: why not just type it as `CanvasRenderingContext2D`? *(The core has no DOM types, so it runs in Node, workers and skia-canvas. Structural typing means real canvases fit anyway.)*
- The test uses a recording sink. That's a useful pattern for testing any drawing code.
